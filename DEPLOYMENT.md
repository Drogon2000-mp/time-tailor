# Time Tailor - Deployment Guide

## 🚀 Render Deployment

This application is configured for deployment on Render using the included `.render.yaml` file.

### Prerequisites

1. **Render Account**: Sign up at [render.com](https://render.com)
2. **MongoDB Atlas**: Set up a MongoDB cluster at [mongodb.com/cloud/atlas](https://www.mongodb.com/cloud/atlas)
3. **Cloudinary Account**: Create an account at [cloudinary.com](https://cloudinary.com) for image storage

### Environment Variables

The following environment variables need to be configured in Render:

#### Required Variables (Must be set manually)

- `MONGODB_URI`: Your MongoDB connection string
  - Example: `mongodb+srv://username:password@cluster.mongodb.net/timetailor?retryWrites=true&w=majority`
  - Get this from MongoDB Atlas → Clusters → Connect

- `CLOUDINARY_CLOUD_NAME`: Your Cloudinary cloud name
- `CLOUDINARY_API_KEY`: Your Cloudinary API key  
- `CLOUDINARY_API_SECRET`: Your Cloudinary API secret
  - Get these from Cloudinary Dashboard → Settings → Product Environment Credentials

- `ESEWA_SECRET_KEY`: Your eSewa secret key (for payment integration)
  - For testing, you can use a placeholder value

#### Auto-configured Variables

These are set automatically in `.render.yaml`:

- `NODE_ENV`: production
- `JWT_SECRET`: Auto-generated by Render
- `CLIENT_URL`: https://time-tailor11.onrender.com
- `SERVER_URL`: https://time-tailor11.onrender.com
- `FRONTEND_URL`: https://time-tailor11.onrender.com
- `ESEWA_MERCHANT_ID`: EPAYTEST (test mode)

### Deployment Steps

#### Option 1: Deploy via Render Dashboard (Recommended)

1. **Connect Repository**
   - Go to [Render Dashboard](https://dashboard.render.com)
   - Click "New +" → "Blueprint"
   - Connect your GitHub/GitLab repository
   - Render will automatically detect the `.render.yaml` file

2. **Configure Environment Variables**
   - After blueprint is detected, you'll be prompted to set environment variables
   - Add all the required variables listed above
   - Variables marked with `sync: false` need manual configuration

3. **Deploy**
   - Click "Apply" to create the service
   - Render will automatically:
     - Install dependencies
     - Build the client
     - Start the server
   - Monitor the deployment logs for any issues

4. **Verify Deployment**
   - Once deployed, visit: `https://time-tailor11.onrender.com/api/health`
   - You should see: `{"status":"ok","message":"Time Tailor API is running"}`

#### Option 2: Deploy via Render CLI

```bash
# Install Render CLI
npm install -g render-cli

# Login to Render
render login

# Deploy from blueprint
render blueprint launch
```

### Post-Deployment

#### MongoDB Atlas Network Access

Render services use dynamic IP addresses, so you need to allow access from anywhere:

1. Go to MongoDB Atlas → Network Access
2. Click "Add IP Address"
3. Select "Allow Access from Anywhere" (0.0.0.0/0)
4. Or add Render's IP ranges if you prefer restricted access

#### Admin User

An admin user is automatically created on first deployment:

- **Email**: admin@timetailor.com
- **Password**: Admin@123

**⚠️ IMPORTANT**: Change this password immediately after first login!

#### Health Check

The application includes a health check endpoint at `/api/health` that Render uses to monitor service health.

### Troubleshooting

#### Build Failures

**Issue**: "Frontend build not found"
```bash
# Solution: The build command should run automatically
# If it fails, check the build logs for errors
npm run build
```

**Issue**: "Module not found" errors
```bash
# Solution: Clear cache and reinstall
rm -rf node_modules package-lock.json
npm install
```

#### Port Conflicts (Local Development)

**Issue**: `EADDRINUSE: address already in use :::5000`

```bash
# Solution 1: Use the helper script
./start-dev.sh

# Solution 2: Kill the process manually
lsof -ti:5000 | xargs kill -9

# Solution 3: Use the npm script
npm run kill-port
npm start
```

#### MongoDB Connection Issues

**Issue**: "MongoDB connection failed"

- Check your `MONGODB_URI` is correct
- Verify IP whitelist in MongoDB Atlas
- Ensure cluster is active (not paused)
- Check MongoDB Atlas service status

**Issue**: "Authentication failed"

- Verify username and password in connection string
- Ensure user has proper database permissions
- Password may need URL encoding (special characters)

#### Cloudinary Issues

**Issue**: "Image upload fails"

- Verify all Cloudinary credentials are correct
- Check Cloudinary usage limits
- Ensure folders exist or auto-creation is enabled

### Monitoring

- **Logs**: View real-time logs in Render Dashboard → Your Service → Logs
- **Metrics**: Monitor performance in Render Dashboard → Your Service → Metrics
- **Health**: Automated health checks via `/api/health` endpoint

### Updating the Deployment

The application auto-deploys when you push to the connected branch:

```bash
git add .
git commit -m "Your changes"
git push origin main
```

Render will automatically:
1. Pull latest changes
2. Run build command
3. Restart the service

### Manual Deploy

To force a manual deploy without code changes:

1. Go to Render Dashboard → Your Service
2. Click "Manual Deploy" → "Deploy latest commit"

### Scaling

On Render's free tier:
- Service spins down after 15 minutes of inactivity
- First request after spin-down may take 30-60 seconds
- Consider upgrading to paid tier for always-on service

### Security Notes

1. **Never commit `.env` files** to version control
2. **Rotate secrets regularly** (JWT_SECRET, API keys)
3. **Use strong passwords** for admin and database users
4. **Enable 2FA** on MongoDB Atlas and Cloudinary
5. **Monitor access logs** for suspicious activity

## 📝 Local Development

### Setup

```bash
# Install dependencies
npm install

# Build client
npm run build

# Start server (with automatic port cleanup)
npm start

# Or use the helper script
./start-dev.sh
```

### Available Scripts

- `npm run build` - Build client for production
- `npm start` - Start production server
- `npm run dev` - Start development server with auto-reload
- `npm run dev:client` - Start client development server
- `npm run kill-port` - Kill process on port 5000

### Environment Variables (Local)

Create `server/.env`:

```env
NODE_ENV=development
PORT=5000
MONGODB_URI=your_mongodb_connection_string
JWT_SECRET=your_jwt_secret_key
CLIENT_URL=http://localhost:5173
SERVER_URL=http://localhost:5000
CLOUDINARY_CLOUD_NAME=your_cloudinary_cloud_name
CLOUDINARY_API_KEY=your_cloudinary_api_key
CLOUDINARY_API_SECRET=your_cloudinary_api_secret
ESEWA_MERCHANT_ID=EPAYTEST
ESEWA_SECRET_KEY=your_esewa_secret
```
